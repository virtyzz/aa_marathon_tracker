# ArcheAge Marathon Tracker

Русскоязычный сервис для личного учёта заданий «Марафона героев». Каждый Discord-аккаунт видит только своих персонажей, отметки и заметки.

## Запуск

1. Скопируйте `.env.example` в серверный `.env` (он игнорируется Git) и заполните Discord OAuth credentials. В Discord Developer Portal укажите callback URL: `${NEXTAUTH_URL}/api/auth/callback/discord` (например `https://aatracker.dayz-map.ru/api/auth/callback/discord`).
2. Запустите PostgreSQL: `docker compose up -d db`.
3. Установите пакеты: `npm install`.
4. Примените миграции: `npx prisma migrate deploy`. Только для первоначального заполнения новой БД выполните `npm run db:seed`.
5. Запустите сервис: `npm run dev`.

Полный запуск в контейнерах: `docker compose up -d --build`. Контейнер приложения применяет только версионированные миграции (`prisma migrate deploy`) и запускает сервер. Seed автоматически не выполняется: перезапуск не переключает активную неделю и не восстанавливает стандартные задания. Только для первоначального заполнения новой БД: `docker compose exec app npm run db:seed`. Новые недели затем создаются и активируются через админку. PostgreSQL не публикует порт наружу; приложение привязано к `127.0.0.1:3100` и должно быть проксировано Nginx-конфигом из `deploy/nginx`.

## Администраторы

Укажите Discord ID через запятую в `ADMIN_DISCORD_IDS`. Серверные маршруты `/api/admin/weeks` и `/api/admin/tasks` проверяют это значение на каждом запросе и пишут действия в `AdminAuditLog`.

## Состав

- Next.js + TypeScript, тёмный адаптивный интерфейс;
- Auth.js/NextAuth с единственным Discord Provider;
- PostgreSQL + Prisma: пользователи, сессии, персонажи, недели, задания, снимки заданий, прогресс, заметки и аудит;
- API с Zod-валидацией и проверкой владения персонажем; недельный лимит 100 XP мягкий: отметки сверх него сохраняются, счётчики показывают максимум 100. Ограничения дней и количества выполнений отдельного задания остаются;
- seed из 14 заданий в автоматически вычисленную текущую неделю (четверг–среда), тесты диапазона, XP и правил доступности.

## Эксплуатация

### Обновление с сохранением прогресса

Обновляйте из прежнего каталога Compose, с прежним именем проекта и томом `postgres_data`. Это обновление не меняет схему БД и не добавляет миграций. Не запускайте seed, `prisma migrate reset` или `docker compose down -v` при обновлении существующего сервера.

Перед обновлением создайте резервную копию внутри контейнера БД и скопируйте её на хост (команды для серверного shell):

```sh
backup="marathon-$(date +%Y%m%d-%H%M%S).dump"
docker compose exec -T db pg_dump -U marathon -d archeage -Fc -f /tmp/marathon-backup.dump &&
docker compose cp db:/tmp/marathon-backup.dump "./$backup"
```

После успешного копирования обновите исходники и пересоберите только приложение:

```sh
docker compose up -d --build --no-deps app
docker compose logs --tail=100 app
curl --fail http://127.0.0.1:3100/api/health
```

Проверьте в интерфейсе прежнюю активную неделю, персонажей и отметки. Все сохранённые выполнения и снимки XP остаются в БД; ограничивается только отображаемая сумма.

Проверка состояния: `curl http://127.0.0.1:3100/api/health`. Ответ не содержит секретов и показывает только статус БД и факт настройки OAuth-proxy. Для обновления выполните `docker compose up -d --build`; для просмотра логов — `docker compose logs -f app`; для отката используйте предыдущий образ и `docker compose up -d`. Удалять остановленные контейнеры можно командой `docker container prune` после проверки списка. Certbot: на новом сервере проверьте `certbot renew --dry-run`; Nginx оставляет `/.well-known/acme-challenge/` для проверки сертификата, а остальной HTTP трафик перенаправляет на HTTPS.
